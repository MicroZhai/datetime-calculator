# 时长与日期范围保护

本项目内部统一使用整数毫秒进行时长计算，并以 `Number.MAX_SAFE_INTEGER` 作为可精确计算边界。

## 1. 单位输入上限

按当前换算因子，正负方向的理论精确范围约为：

- 天：`104,249,991 天`
- 小时：`2,501,999,792 小时`
- 分：`150,119,987,579 分`
- 秒：`9,007,199,254,740 秒`

超过范围时不继续加入表达式，错误文案必须说明当前单位的上限，不使用笼统的“数值过大”。

## 2. 累计计算上限

单个片段都合法，不代表多行 `+ / -` 的累计结果一定合法。每一步累计仍必须保持在安全整数毫秒范围内；超限时提示：

`计算结果超出精确范围（约 ±1.04 亿天）`

不得为追求更大范围而静默接受失去整数精度的 Number 运算。

## 3. 日期范围与时长范围分离

日期锚点只负责把时长结果映射为具体年月日，不决定时长本身是否有效。

JavaScript `Date` 的可表示范围约为 Unix Epoch 前后 `100,000,000 天`。因此可能存在：

- 时长仍在安全整数范围内；
- 但 `日期 + 时长` 已无法映射为有效 `Date`。

这种情况下：

- 时长结果继续正常显示；
- 结束日期显示 `结束日期超出范围`；
- 可访问说明为“时长仍可计算，但具体结束日期超出浏览器可表示范围”。

## 4. 边界测试

至少保持以下回归用例：

- `3,000,000 天`：允许；
- `104,249,991 天`：允许；
- `104,249,992 天`：拒绝；
- `300,000,000 天`：拒绝；
- `2,501,999,792 小时`：允许；
- `2,501,999,793 小时`：拒绝；
- 开启日期后，超出 `Date` 范围只降级结束日期，不影响合法时长结果。
